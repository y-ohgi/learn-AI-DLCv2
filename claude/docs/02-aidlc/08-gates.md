# 2.8 承認ゲートと3つの対話モード

AI-DLC を「体験」したときに、いちばん直接触るのがここです。

## 3つの対話モード（Tri-Mode）

ステージが入力を求めるとき、3つのモードから選べます。

```
▸ Choose interaction mode:
  (1) Guide Me   — エージェントが構造化された質問をする
  (2) Edit File  — 成果物ファイルに直接書き込む
  (3) Chat       — 自由な議論
```

| モード | 進み方 | 向く場面 |
| --- | --- | --- |
| **Guide Me** | エージェントが質問を1つずつ（またはバッチで）提示、あなたが答える | エージェントに主導させたい。抜け漏れを防ぎたい。**初回はこれ** |
| **Edit File** | 空欄の質問ファイルが記録ディレクトリに現れる。自分のペースで埋める | 既に答えが決まっている。書いた方が速い。人に相談してから埋めたい |
| **Chat** | 自由に議論。エージェントが決定を抽出し、質問ファイルに書き戻す | 要件がまだ固まっていない。探索したい |

**3つとも「質問ファイル」に収束します。** これが決定の正式な記録です。だからモードは**ステージの途中で切り替えても進捗が失われません**。

この設計の意味：**会話の柔軟さと記録の確実性を両立させている**。Chat で自由に話しても、決定はファイルに残る。

## 承認ゲート

Initialization の3ステージを除き、**すべてのステージの最後に承認ゲート**があります。

```
▸ How would you like to proceed?
  (1) Approve         — Continue to [次のステージ名]
  (2) Request Changes — 修正のフィードバックを渡す
```

`[次のステージ名]` は**エンジンが計算した実際の次ステージ**が表示されます（例：「Continue to NFR Requirements」）。最終ステージなら「Complete workflow」。推測ではないので常に正確です。

- **Approve** → エンジンがステージを完了にし、`aidlc-state.md` を更新し、進捗行を表示して次へ進む
- **Request Changes** → フィードバックを渡すとエージェントが修正し、ゲートを再提示

表示された選択肢に一致しない返答をした場合は、**何も記録されずゲートが開いたまま**選択肢が再表示されます。誤操作で進んでしまうことがない設計です。

## エスケープハッチ（3回ルール）

差し戻しを繰り返しても収束しないことがあります。そのための仕組み：

- 2回目の差し戻しの後、「次のサイクルでエスケープハッチが有効になる」旨の注記が出る
- **3回目以降**、「Accept as-is（現状のまま受け入れる）」という選択肢が追加される

無限ループを防ぎつつ、諦める選択が明示的に記録される形になっています。

## スキップしたステージを後から足す

Ideation / Inception のゲートでは「**Add Skipped Stage**」という選択肢も出ます。
「スコープを軽くしすぎた」と気づいたときに、スキップされたステージをワークフローに挿入できます。決定は scope ツールが記録します。

## human-presence check（人がいることの確認）

ここは v2 の特徴的な安全機構なので、少し詳しく。

承認ゲートは **「人間の対話の痕跡」を要求します**。

- あなたがプロンプトを打つ、またはネイティブの質問ピッカーで答えると、監査台帳に `HUMAN_TURN` イベントが記録される
- **承認（および明確化質問への回答）は、前回のゲート解決以降に `HUMAN_TURN` が記録されていないと拒否される**

これが証明するのは「**人がその場にいて、順序どおりに操作した**」ことです。決定文の著者が人間であることまでは証明しません（ハーネスによっては信頼できるプロンプト内容を露出しないため）。
加えて、コンダクター／モデルの自己申告（「私が承認します」的な文言）を認識して弾く防御ラインもありますが、ラベルのない文言は認証されません。

### 無人自動化の扱い

人がいない状態でプロンプトを流す自動化は、実行プロセスに **`AIDLC_UNATTENDED=1`** を設定する必要があります。

- このフラグがある場合、**すべてのハーネスが権威を持つ `HUMAN_TURN` を発行しません**
- 結果として、承認ゲートとインタビューゲートは**待ち続けます**
- 人が引き継ぐときはフラグを外して、改めて応答する

「無人で全自動 33 ステージ」はできない、というのが AI-DLC の設計上の立場です。**これは制限ではなく主張です。**

なお、ピッカーが `HUMAN_TURN` を記録しないハーネスもあるので、その場合は一度短く「approve」と打つと記録されます（そもそも台帳に人間ターンが一度も無い環境では、ゲートは fail-open して要求しません）。

## ゲートの数を把握しておく

スコープ確認時に**ゲート数が表示されます**。

- `bugfix`：9 ステージ / 5 ゲート程度
- `feature`：33 ステージ / 29 ゲート

**29 回のゲートは、人間の集中力の問題として真剣に受け止めるべき数字です。** これが 1.4 で挙げた「承認の空洞化」のリスクそのものです。
対策は3つ：

1. **スコープを適切に選ぶ**（そもそもゲート数を減らす）
2. **walking skeleton の ladder prompt で自律モードを意識的に選ぶ**（最初の1回を真剣に見て、以降は差分レビューに集中する）
3. **重要なゲートを事前に決めておく**（要件・Units 分解・walking skeleton の3つは必ず精読する、など）

3つ目はチーム規律の話なので、第4部で扱います。

## この章のまとめ

- 対話モードは Guide Me / Edit File / Chat の3つ。すべて質問ファイルに収束し、途中で切り替え可能
- 全ステージ（Initialization 除く）にゲート。次ステージ名はエンジンが計算した実際の値
- 3回差し戻すと「Accept as-is」が出る。スキップしたステージを足すこともできる
- 承認には `HUMAN_TURN` の記録が必要。無人自動化（`AIDLC_UNATTENDED=1`）ではゲートが待ち続ける
- ゲート数（最大29）は人間側のボトルネック。スコープ選択と自律モードで管理する
