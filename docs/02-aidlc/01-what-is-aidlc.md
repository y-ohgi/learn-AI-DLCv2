# 2.1 AI-DLCとは何か

## 一言でいうと

**AI-DLC（AI-Driven Development Life Cycle）は、AWS が定義した「AI を主役に置いた開発ライフサイクルの方法論」**です。

従来の SDLC が「人間が作り、AI が手伝う」前提だったのに対し、AI-DLC は **「AI が作り、人間が方向づけて承認する」**前提でライフサイクルを組み直します。

公式ドキュメントの表現を借りると、AI-DLC の核は次の一点です。

> AI Powered Execution with Human Oversight
> （AI が実行し、人間が監督する）

具体的には、AI が詳細な作業計画を体系的に作り、**自ら明確化のための質問を投げ**、**重要な意思決定は人間に委ねる**。なぜなら、ビジネス要件の文脈的理解を持つのは人間だけだから、という論理構成です。

## 「方法論」と「実装」を必ず区別する

ここが最初の関門です。AI-DLC という語は2つのものを指します。

| | 何か | どこにあるか |
| --- | --- | --- |
| **方法論としての AI-DLC** | フェーズ・儀式・原則の定義。ツール非依存 | AWS の DevOps ブログ記事と Method Definition Paper |
| **実装としての AI-DLC Workflows** | 方法論を実行可能にした OSS。Claude Code などの上で動く | GitHub `awslabs/aidlc-workflows` |

本教材で「v1 / v2」と呼ぶのは、主に**実装側のバージョン**です。

- **v1** = 2025年11月に公開された、ルールファイル（Markdown）ベースの実装。各ハーネスの設定ディレクトリに `core-workflow.md` を置いて動かす形式。工程の進行判断は LLM の判断に依存していた
- **v2** = TypeScript による**決定論的エンジン**を持つネイティブ実装。2026年4月にプレビュー系列が始まり、2.0.0 が GA。以降 2.x 系で継続的に更新

そして方法論そのものも、v2 実装に合わせて「3フェーズ」から「5フェーズ33ステージ」へと具体化されています。この関係を押さえておくと、Web 上の記事が3フェーズを語っていたり5フェーズを語っていたりする理由が分かります。

## なぜ AWS が作ったのか

背景として引用されることが多いのが、Amazon 社内の実績です。Andy Jassy が公表した例では、**Amazon Bedrock の推論エンジンを6人のエンジニアが 76 日で再構築**した（当初見積もりは 40 人・1年）とされています。

この種の数字は前提条件が不明なので、そのまま自社に当てはめるべきではありません。ただし「AI を前提に組み直すと、チーム構成と期間の常識が変わりうる」という主張の根拠として提示されている、という文脈は理解しておくとよいでしょう。

## AI-DLC が主張する3つの転換

方法論としての AI-DLC は、従来のアジャイル/スクラムに対して3つの転換を主張します。

### 転換1：スプリント → Bolt

2週間のスプリントではなく、**数時間〜数日の作業サイクル（Bolt）**を単位にする。AI の生成速度に合わせて、計画〜実装〜レビューのループを短くする。

### 転換2：非同期の役割分担 → Mob（同期的な集団作業）

要件を PdM が書き、設計をアーキテクトが引き取り、実装をエンジニアが受け取る、という**引き継ぎの連鎖をやめる**。
AI が質問と草案を出し、プロダクト・開発・QA が**同じ場で同時に**それを検証する。これを **Mob Elaboration**（要件の集団詳細化）、**Mob Construction**（設計・実装の集団構築）と呼びます。

引き継ぎは情報が失われる場所である、という認識が根底にあります。

### 転換3：AI は補助 → AI が起点

タスクの分解、要件の草案、設計の選択肢、コード、テストを **AI が先に出す**。人間の仕事は「白紙から書く」ことから「提示されたものを判断し、方向づける」ことに変わる。

これは楽になるという話ではありません。**単位時間あたりの意思決定の密度が上がる**という話です。実際に AI-DLC を体験した人が最初に驚くのはここで、「AI が全部やってくれる」どころか「延々と判断を求められる」という感想になります。

## この章のまとめ

- AI-DLC は AWS が定義した AI-native な開発ライフサイクルの方法論。「AI が実行し、人間が監督する」
- 「方法論としての AI-DLC」と「実装としての AI-DLC Workflows」を区別する。v1/v2 は主に実装のバージョン
- 主張は3つ：スプリント→Bolt、引き継ぎ→Mob、AI は起点
- 楽になる方法論ではなく、意思決定の密度が上がる方法論

次章で、方法論としての v1（3フェーズ）を押さえます。v2 の 33 ステージは、この骨格を細分化したものです。
