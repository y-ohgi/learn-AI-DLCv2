# 1.1 あなたの AI 利用はどこにいるか

この章は、AI-DLC の話を始める前の準備です。あなたが今どのように AI を使っていて、なぜそこから「方法論」という少し重たい言葉の話に進むのかを、先に共有しておきます。AI-DLC の中身は第 2 部から始まります。

## この章で学ぶこと

- 自分の AI Agent 利用を「補完 → チャット → エージェントに指示して差分をレビュー」という流れの中に位置づけられる。
- 個人では効くやり方が、チームとプロジェクトになるとなぜ崩れるのかを、自分の言葉で説明できる。
- この本で「方法論」と呼ぶものが何を指し、何を指さないかを区別できる。

## あなたの日常はどこにいるか

多くの読者の一日は、たぶんこう始まります。エディタか端末で Claude Code を開き、「この関数にリトライを足して」「このテストが落ちる原因を直して」と一文で指示する。数十秒後に差分が返ってくる。目で追い、必要なら「ここは既存のヘルパーを使って」と言い直し、納得したらコミットする。数年前なら自分で書いていた部分の多くを、今は「読んでレビューする」仕事に置き換えています。

この使い方には、はっきりした特徴があります。判断の単位が「一回のやりとり」で、文脈はあなたの頭の中にあり、成果物は差分だけです。何を作るかを決めたのも、なぜそう直したのかを知っているのも、あなた一人です。うまく回っているうちは、これで十分に速い。

## 個人では効くのに、チームでは崩れる理由

ところが同じやり方を 3 人のチームで、3 か月のプロジェクトでやると、次のようなことが起きます。

- **判断が残らない。** 「なぜこの設計にしたか」は、その日のチャット履歴の中にしかなく、翌週には誰も参照できない。
- **前提がずれる。** A さんの Agent は「テストは後で」と教えられ、B さんの Agent は「テスト先行で」と教えられている。同じリポジトリに、違う流儀の差分が混ざる。
- **止まるべき場所で止まらない。** 要件があいまいなまま実装が進み、レビューの段階で「そもそもこれは要らなかった」と分かる。人が判断すべき地点が、やりとりの流れの中に埋もれている。
- **速さが逆転する。** 個人で得た時間を、チームでは「誰が何を決めたのかを掘り起こす時間」に払い戻す。

要するに、個人の AI 利用は「人が頭の中で持っている文脈と判断」に支えられていて、それは共有もスケールもしない、ということです。これはツールの性能の問題ではなく、仕事の進め方の問題です。

## 「方法論」という言葉で指すもの

この本で「方法論」と呼ぶのは、AI と人が一緒に仕事を進めるときの、次の 3 つの決めごとの束です。

1. **順序** — 何を先に決め、何を後に作るか。要件を固めずにコードを書かせない、というような段取り。
2. **判断の地点** — どこで人が立ち止まって決めるか。AI に任せる部分と、人が承認する部分の境目。
3. **記録** — 決めたことと、その理由を、後から誰が読んでも分かる形で残す方法。

逆に、この本で「方法論」に含めないものもはっきりさせておきます。特定のモデルの選び方、プロンプトの書き方のコツ、エディタの設定は扱いません。それらは道具の話で、道具が変わっても残るのが方法論です。

AI-DLC はこの 3 つに答えを持つ方法論の 1 つで、しかも「決めごと」を文章で配るだけでなく、順序と判断の地点をソフトウェアとして実装しているところに特徴があります。AI-DLC v2 の配布物は、決定論的なエンジンが「次に何をするか」を決め、あなたの会話相手であるコンダクターがそれを実行して結果を報告する、という往復で動きます。そして各ステージの後に承認ゲートを置き、あなたが確認して承認するまで先に進みません。これが「判断の地点」をツールで実装する、ということの具体例です。中身は第 3 部で順に見ていきます。

## AI 開発の歴史と種類の要点

AI 開発の歴史を詳しく振り返ることは、この本の目的ではありません。要点だけ言うと、AI のコーディング支援は「一行を補完する」道具から始まり、「会話で相談する」道具になり、今は「指示を受けて複数のファイルを編集し、コマンドを実行する」エージェントになりました。そしてエージェントが実用になったとたんに、前の節で見た「チームで崩れる」問題が表に出て、進め方を定める方法論がいくつも提案されるようになりました。AI-DLC はその中の 1 つで、AWS が公開した方法論を起源に持ちます。

## まとめ

- 今の AI 利用は「エージェントに指示して差分をレビューする」段階にあり、文脈と判断はあなたの頭の中にある。
- それはチームとプロジェクトでは共有もスケールもしないため、順序・判断の地点・記録を定める「方法論」が必要になる。
- AI-DLC はその方法論の 1 つで、順序と判断の地点をエンジンと承認ゲートとして実装している。
