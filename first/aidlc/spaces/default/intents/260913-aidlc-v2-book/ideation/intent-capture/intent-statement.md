# Intent Statement — AI-DLC v2 教材（first 版）

## Problem Statement

- AI Agent（Claude Code / Cursor / Codex CLI など）を実務で使っているが、AI 駆動開発の「方法論」には触れてこなかったエンジニアが、AWS の AI-DLC v2 を体系的に学べる日本語教材が存在しない。[desc] [Q1] [Q2]
- 既存の教材（claude 版）は AI-DLC Workflows 2.7.1 時点の情報に基づいており、2.8.0 以降の配布方法の変更を反映していない。[Q1]
- 「AI に直接書かせた教材」と「AI-DLC のワークフローを回して作った教材」を読み比べられる実例が存在せず、方法論の効果を読者が自分で確かめられない。[Q1] [Q4] [Q9]

## Target Customer

- 主たる読者は、AI Agent を日常的に使うが AI 駆動開発の方法論を知らないエンジニアである。依頼者自身がこのペルソナに該当する。社内外を問わず、GitHub Pages で公開する。[Q2] [Q9] [desc]
- 読者が抱える痛みは、素の Agent 利用が個人では効くのに、チームとプロジェクトではスケールしないことである。[Q2]
- AI-DLC をすでに使っている実務者や導入判断者は主たる読者ではない（Q2 の選択肢 B・C は選ばれていない。除外要件ではなく、最適化の対象外という意味である）。[Q2]

## Initiative Trigger

- AI-DLC 2.8.0（2026-09-08 リリース）で配布方法がネイティブインストーラに変わり、既存教材のインストール手順が陳腐化した。[Q4]
- 「AI-DLC そのものを使って教材を作る」ことで方法論を実地検証し、その記録（要件・Unit・監査ログ）ごと教材にしたいという動機がある。[Q4] [Q9] [desc]

## Initial Scope Signal

- **workflow-selected**: `docs-book`。Q8 の設問文に示したステージ構成（意図把握・スコープ定義・実践発見・要件分析・ドメイン設計・Unit 分解・デリバリー計画・機能設計・執筆・ビルド検証・公開確認）で開始された。[scope] [Q8]
- **user-confirmed product boundary**: 製品は「HonKit 教材とその GitHub Pages への公開（`/first/`）」のみであり、アプリケーションコード・クラウドインフラ・運用面は含まない。読者用の演習リポジトリやサンプルアプリは含まない。[Q8] [Q9]

## Assumptions & Open Questions

- 読者は日本語で読む。初期説明・依頼文・既存教材が日本語であることから推定したもので、多言語対応は求められていないと解釈している。[assumption]
- 依頼者の代理として行った回答（特に SM1〜SM3 の成功指標と製品境界）は、依頼者本人が後日この記録を見て修正する可能性がある。修正が入った場合は新しいワークフロー（intent）で扱う。[assumption]
- claude 版は意図・読者像・ゴールに関する代理回答の根拠に限って用い、AI-DLC の事実記述は claude 版ではなく 2.8.2 の一次情報で裏取りする（Q6 の影響者と整合）。[assumption]
- 開いた問い: SM2 の確認手段として「主張→出典の対応表」を成果物に採用するかは scope-definition で決める。[assumption]
- 開いた問い: claude 版との住み分け（独立執筆／出典明記の再利用／リンク参照のみ）は scope-definition で確定する。[assumption]
