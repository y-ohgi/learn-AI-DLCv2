# Intent Statement — AI-DLC v2 教材（first 版）

## Problem Statement

- AI Agent（Claude Code / Cursor / Codex CLI など）を実務で使っているが、AI 駆動開発の「方法論」には触れてこなかったエンジニアが、AWS の AI-DLC v2 を体系的に学べる日本語教材が存在しない。[desc] [Q1] [Q2]
- 既存の教材（claude 版）は AI-DLC Workflows 2.7.1 時点の一次情報に基づいており、2.8.0 以降の配布方法の変更（`dist/` のコピーからネイティブ `aidlc` コマンドと `aidlc config` へ）を反映していない。[Q1]
- 「AI に直接書かせた教材」と「AI-DLC のワークフローを回して作った教材」を読み比べられる実例が存在せず、方法論の効果を読者が自分で確かめられない。[Q1] [Q4]

## Target Customer

- 主たる読者は、AI Agent を日常的に使うが AI 駆動開発の方法論を知らないエンジニアである。社内外を問わず、GitHub Pages で公開する。[Q2] [desc]
- 読者が抱える痛みは「素の Agent 利用は個人では効くが、コンテキストの揮発・決定記録の欠落・レビュー容量の不足によってチームとプロジェクトではスケールしない」ことである。[Q2]
- AI-DLC をすでに使っている実務者や導入判断者は主たる読者ではない（Q2 の選択肢 B・C は選ばれていない。除外要件ではなく、最適化の対象外という意味である）。[Q2]

## Success Metrics

| # | 指標 | 測り方 | Source |
| --- | --- | --- | --- |
| SM1 | 読了後に読者が AI-DLC v2 を自分の環境にインストールし、1 つのワークフローを承認ゲートまで通せる | ハンズオン章の手順が 2.8.2 の実環境で再現可能であること（本ワークフロー自身の実行記録で検証） | [Q3] |
| SM2 | 教材中の AI-DLC に関する事実記述が、すべて 2.8.2 の一次情報（公式ドキュメントまたはコード）で裏取りされている | 未裏取りの断定がゼロ。各章の主張→出典の対応表で確認 | [Q3] [Q6] |
| SM3 | GitHub Pages の `/first/` で公開され、`honkit build` が成功し、教材内のリンクがすべて解決する | ビルド成功・リンクチェック・公開 URL の HTTP 200 | [Q3] [Q5] |

## Initiative Trigger

- AI-DLC 2.8.0（2026-09-08 リリース）で配布方法がネイティブインストーラに変わり、既存教材のインストール手順が陳腐化した。[Q4]
- 「AI-DLC そのものを使って教材を作る」ことで方法論を実地検証し、その記録（要件・Unit・監査ログ）ごと教材にしたいという動機がある。[Q4] [desc]

## Initial Scope Signal

- **workflow-selected**: `docs-book`（アダプティブコンポーザーが提案し承認されたカスタムスコープ。14/33 ステージ、Standard 深度、テスト戦略 Minimal、Change Control relaxed）。[scope]
- **user-confirmed product boundary**: 製品は「HonKit 教材とその GitHub Pages への公開」のみであり、アプリケーションコード・クラウドインフラ・運用面は含まない。読者用の演習リポジトリやサンプルアプリは含まない。[Q8]

## Assumptions & Open Questions

- 読者は日本語で読む。初期説明と既存教材が日本語であることから推定したもので、多言語対応は求められていないと解釈している。[assumption]
- 依頼者の代理として行った回答（特に SM1〜SM3 の成功指標と製品境界）は、依頼者本人が後日この記録を見て修正する可能性がある。修正が入った場合は新しいワークフロー（intent）で扱う。[assumption]
