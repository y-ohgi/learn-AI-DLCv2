# Stakeholder Map — AI-DLC v2 教材（first 版）

## Key Stakeholders

| ステークホルダー | 役割 | 関心事 | Source |
| --- | --- | --- | --- |
| 依頼者（リポジトリオーナー） | 発注者・最終決定者 | `/first/` での公開完了、事実の正確性（2.8.2 の一次情報に基づくこと）、claude 版との住み分け | [Q5] [Q6] |
| 読者（AI Agent を使うが方法論を知らないエンジニア） | 成果物の利用者 | 短時間で概念とハンズオンを掴めること、手順が現行バージョンで動くこと | [Q5] [Q2] |
| コンダクター（本ワークフローを回す AI） | 依頼者の代理回答者・執筆者 | 代理判断の根拠を claude 版に求め、記録に残すこと | [Q6] [Q7] |
| AI-DLC の一次情報（awslabs/aidlc-workflows 2.8.2 のドキュメントとコード） | 事実の裁定者（人ではない影響源） | 教材の事実記述の正誤を決める | [Q6] |

## Decision-makers vs. Influencers

| 区分 | 誰 | 権限・影響 | Source |
| --- | --- | --- | --- |
| 決定者 | 依頼者 | スコープ・優先度の最終決定。ただし本ワークフロー中は介入しない | [Q6] |
| 代理決定者 | コンダクター | 依頼者不在の間、claude 版を参照して代理判断し、根拠を記録する | [Q6] |
| 影響者 | AI-DLC 2.8.2 の一次情報 | 記述内容の正誤に対する拘束力を持つ | [Q6] |
| 影響者 | 読者 | 章構成・深さ・ハンズオンの粒度に対する要求（Q2 の痛みとして反映） | [Q2] [Q5] |

## Communication Requirements

| 要件 | 内容 | Source |
| --- | --- | --- |
| 記録 | 各ステージの成果物・質問ファイル・監査ログを記録ディレクトリ（`first/aidlc/`）に残す | [Q7] |
| 報告 | 完了時に PR とチャットの要約で報告する。途中の定期報告は不要 | [Q7] |
| 承認 | ワークフロー中の承認ゲートはコンダクターが代理で判断し、判断ログを残す | [Q6] [Q7] |
