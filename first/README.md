# はじめに

この本は、AI-DLC（AI-Driven Development Life Cycle、AI 駆動開発ライフサイクル）を知らないエンジニアのために書いた、AI-DLC v2 の入門書です。日々 Claude Code などの AI Agent に指示を出し、返ってきた差分をレビューしている人が、「個人では回るのに、チームとプロジェクトになるとなぜ崩れるのか」から出発して、AI-DLC v2 の考え方と実物の仕組みを順に理解し、自分の環境で最初のワークフローを動かし、最後に「この本そのものが AI-DLC で作られた記録」を読めるようになることを目指します。

## 対象読者と前提

| 前提 | 必要か | 補足 |
| --- | --- | --- |
| AI Agent の実務利用 | 必要 | Claude Code に指示してコードを書かせ、差分をレビューするのが日常であること |
| Git と GitHub の基本操作 | 必要 | ブランチ、コミット、Pull Request が分かること |
| ターミナル操作 | 必要 | `curl` と `git` が使えること |
| AI 駆動開発の方法論の知識 | 不要 | AI-DLC の v1 も v2 も知らない前提で書いています |
| AWS の知識 | 不要 | AI-DLC v2 の配布物は Amazon Bedrock を既定にしていますが、使わない手順も書きます |

## この本の立ち位置

この本が扱う「AI-DLC v2」は、GitHub の `awslabs/aidlc-workflows` リポジトリで公開されている 2.x 系の実装のことで、記述はすべて **2.8.2**（タグ `v2.8.2`、コミット `355903d`）に固定しています。AI-DLC の事実は、そのタグのドキュメントとコード、この本のリポジトリにコミットしてあるインストール済みのランタイム、そしてこの本を作ったワークフローの記録の 3 つだけを根拠にし、根拠を示せないことは断定しません。版を固定したのは、AI-DLC v2 の開発が速く、数か月で配布方法や画面が変わるからです。読者が別の版を使っている場合は、章末の出典から差分を確かめられます。

同じサイトには、Claude Code に直接書かせた姉妹本「AI-DLC v2 入門」（以下、claude 版）があります。claude 版は AI 開発の歴史や他手法との比較、チームへの導入を広く扱っています。この本は claude 版の文章を再利用せず独立に書き下ろし、重複しやすい話題は要点だけを述べて claude 版の該当章へリンクします。2 冊を並べて読むと、「AI に直接書かせた教材」と「AI-DLC のワークフローを回して作った教材」の違いを自分で確かめられます。

## 読み方

部の順に読めば、前の章までの知識だけで読めるように書いています。

- **第 1 部 読者の現在地** — あなたの AI 利用がどこにいて、なぜ「方法論」の話になるのか。
- **第 2 部 AI-DLC の概念** — AI-DLC とは何か、「v2」「v1」という言葉は何を指すのか、2.8.2 が定義する用語。
- **第 3 部 v2 の仕組み** — インストールから、エンジンとコンダクター、ステージ、スコープ、エージェント、承認ゲートと監査、学習ループ、Construction の進め方まで。
- **第 4 部 ハンズオン** — 自分の環境に 2.8.2 を導入し、最初のワークフローの最初の質問が出るところまで。
- **第 5 部 ケーススタディ** — この本自身がどう作られたか。計画、質問と回答、レビューと差し戻し、記録の読み方、そして限界。
- **付録** — 用語集、コマンド早見、出典一覧、つまずきポイント。

## 出典の読み方

各章の末尾に `## 出典` 節を置き、その章の事実主張を裏付ける一次情報を 1 行ずつ列挙しています。行の形は次のとおりです。

```text
- [名前空間] パス 位置 — その出典が裏付ける主張
```

名前空間は 4 つだけです。

| 名前空間 | 何を指すか | 開き方 |
| --- | --- | --- |
| `[2.8.2]` | `awslabs/aidlc-workflows` のタグ `v2.8.2` のリポジトリ相対パス（`docs/…`、`core/…`） | `https://github.com/awslabs/aidlc-workflows/blob/v2.8.2/` の後にパスを続ける |
| `[runtime]` | この本のリポジトリにコミットされた、インストール済みのランタイム（`first/.claude/…`） | この本のリポジトリで開く |
| `[record]` | この本を作ったワークフローの記録（`first/aidlc/…`） | この本のリポジトリで開く |
| `[推定]` | 一次情報で確定できないが書く価値のある推論。本文側にも「（推定）」を付けています | 根拠と確定できない理由を同じ行に書きます |

位置は見出し名（`§ …`）か、関数名・サブコマンド名・イベント名で示し、行番号は使いません。パスはリンクにせず文字列のまま書いています。`first/.claude/` と `first/aidlc/` は HonKit の公開対象から外しているため、Web 上ではリンクとして辿れないからです。
